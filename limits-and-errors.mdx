The API uses Stellar Ecosystem Proposal (SEP) response formats. It does not use the Nostro mobile API's `success` / `data` wrapper. A typical error is:

```json
{"error": "Description of the rejected request"}
```

Read the HTTP status and response together. Some protocol errors include additional fields. Error messages are not stable machine codes.

## Errors and what to do

| Input or situation | HTTP status | Meaning | Fix |
| --- | --- | --- | --- |
| Missing fields, wrong asset, unsupported destination or mismatched name | `400` | Invalid request | Use the exact test profile and the endpoint's example. |
| Bank and wallet fields together, or quote method differs from receiver | `400` | Inconsistent destination | Select one destination and match its quote method. |
| Outside 100–2,500 XOF, or fractional XOF | `400` | Invalid amount | Choose an allowed amount; send only one of `sell_amount` and `buy_amount`. |
| Missing or expired token | `401` | Authentication failed | Start a new session and replace the Bearer token. |
| Unauthorized sending account or payment binding | `403` | This session cannot perform the operation | Use the account returned by your session and its payment IDs. |
| Unknown customer, quote, payment or route | `404` | Resource not found | Use an ID from your live response, not a static example. |
| Expired quote or changed instructions using an already-bound quote | `409` | Quote conflicts with the request | For an unfunded new payment, obtain a new quote. For an existing payment, retain its IDs and reconcile. |
| Payment creation or funding needs reconciliation | `409` | Outcome is not settled yet | Retry the same request or payment ID; do not create a second payment. |
| Request body exceeds 64 KiB | `413` | Payload too large | Send only the documented fields. |
| Unsupported body format | `415` | Content type not accepted | Use `Content-Type: application/json` for JSON requests. Bodyless helper calls need no body. |
| Shared per-minute request cap | `429` | Too many requests | Wait about a minute, then retry. |
| Total sponsor budget exhausted | `429` | The shared 50-payment funding budget is used | Contact Nostro; waiting does not replenish this budget. |
| Provider failure, unavailable funding or shared quote liquidity exhausted | `500` / `503` | Processing cannot complete now | Keep IDs, check payment status, and contact Nostro if persistent. |

There is no documented `509` response. A timeout is not proof that a write failed.

## Shared limits

| Limit | Value |
| --- | --- |
| Payment amount | 100–2,500 whole XOF; 0.2–5 test USDC |
| Exchange rate | 500 XOF per USDC |
| Service fee | 0; the sponsor pays the separate Stellar network fee |
| Quote lifetime | Ten minutes; use its `expires_at` |
| Overall gateway requests | 180 per 60-second window |
| New sandbox sessions | 10 per 60-second window |
| Funding requests | 15 per 60-second window |
| Total sponsored payments | 50 persisted funding records across the shared demo |

Request limits are shared across visitors, not per user. The gateway currently does not return a `Retry-After` header.

The pinned platform reports `min_amount: 0` in SEP-31 discovery because that field uses whole numbers. The quote service enforces the actual **0.2 USDC / 100 XOF minimum**.

## Safe retries

- **Create:** retry the identical request with the same quote and customer IDs. It resolves to the same payment; changed instructions conflict.
- **Fund:** retry the same payment ID. Funding records preserve the signed transaction and reconcile its hash.
- **Track:** `funding_confirmed` in the funding response proves on-chain funding only. Read payment status until `completed` confirms payout. A `pending_external` payment is still awaiting the off-chain result.
- **Stop on an error:** retain the payment ID and provider references. Do not automatically create another payment or assume a refund happened.
