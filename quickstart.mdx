This walkthrough uses Stellar Testnet and PI-SPI sandbox. Use the [test beneficiaries](/test-beneficiaries). No real money is involved.

<Tip>
  Everything runs in this site's **Try it** playground. No wallet, terminal, installation or local helper is needed. The API is hosted at `https://sandbox-api.nostro.finance`.

  Choose request examples from the dropdown beside **cURL** (for example, **Sender** or **BankQuote**). This fills the request fields. Replace any `<...>` placeholders with values from your own responses.

  After **Send**, wait for the live response panel at the top right to show a status such as **200 OK**, **201 Created** or **202 Accepted**. Copy IDs and tokens from that panel. The response examples below it are illustrations, not the result of your request. Save the sender ID before submitting the receiver on the same page.

  Paste only the token into the Bearer field, without adding the word `Bearer`. Mintlify may keep it between pages; replace it if you start a new session.
</Tip>

## 1. Start a session

Open [Start a sandbox session](/api-reference/sandbox/start-a-sandbox-session?playground=open) and click **Send**. No body is needed.

Save these two values:

- **token**: paste it into the Bearer field on the following pages.
- **account**: the sending partner's Stellar public key. Use it when registering both customers.

## 2. Register the sender and receiver

Open [Register a customer](/api-reference/customers/register-a-customer?playground=open). First select **Sender**, paste your session `account`, and send. Save its `id` as **sender_id**.

Then select **BankReceiver** or **WalletReceiver**, use the same session `account`, and send. Save this `id` as **receiver_id**.

The **sender** is the person sending money. The **receiver** owns the destination bank account or wallet. Our Anchor integration requires both customer IDs, regardless of the destination type. The partner’s Stellar `account` identifies the API caller; it is not either person’s bank account.

|  | Bank account | Mobile money |
| --- | --- | --- |
| Name | Amina Diop | Lamine Tall |
| Institution | `BIMAO_SANDBOX` | `PI_SPI_EME_CI_SANDBOX` |
| Destination | Account `31432` | Number `+2250700000000` |
| Quote method | `bank_account` | `mobile_money` |

You can [read customer status](/api-reference/customers/read-customer-requirements-or-status?playground=open) with each returned ID. Both must be `ACCEPTED`.

## 3. Choose an amount and get a quote

Open [Get a payment quote](/api-reference/quotes/get-a-payment-quote?playground=open). Select **BankQuote** or **WalletQuote** to match your receiver.

Change **sell_amount** to the USDC amount you want to send. For example:

| USDC sent | XOF received |
| --- | --- |
| `0.2` | `100` |
| `1` | `500` |
| `2` | `1000` |
| `5` | `2500` |

The minimum is **100 XOF**, the maximum is **2,500 XOF**, and the receiver must get whole XOF. You can instead provide `buy_amount` in XOF; remove `sell_amount` first. Never provide both.

Save the quote **id** and **sell_amount**. The quote is valid for ten minutes.

### What the quote fields mean

- **sell_asset**: the currency you send—USDC.
- **buy_asset**: the currency the receiver gets—XOF.
- **price**: the exchange rate before fees. `0.002` means **0.002 USDC for one XOF**, which is **500 XOF per USDC**.
- **fee.total**: the service charge. It is `0` here.
- **fee.asset**: the currency used for the service charge.
- **total_price**: the exchange rate including fees. It equals `price` here because the fee is zero.

The Stellar network fee is separate; the sandbox sponsor pays it.

### Why is the USDC identifier so long?

Stellar's quote standard uses `stellar:<currency>:<issuer>`. The issuer distinguishes the intended USDC asset from other assets with the same name. Keep the prefilled value:

```json
"sell_asset": "stellar:USDC:GBBD47IF6LWK7P7MDEVSCWR7DPUWV3NY3DTQEVFL4NAT4AQH3ZLLFLA5"
```

XOF uses the currency-code format `iso4217:XOF`. These are [standard Stellar quote identifiers](https://github.com/stellar/stellar-protocol/blob/master/ecosystem/sep-0038.md#asset-identification-format).

## 4. Create the payment

Open [Create a payment](/api-reference/payments/create-a-payment?playground=open).

- Set `sender_id` from sender registration.
- Set `receiver_id` from receiver registration.
- Set `quote_id` from your quote.
- Set `amount` to the quote's **sell_amount**.

Send and save the payment **id**. This creates the instruction; funds have not moved yet. Repeating the identical request returns the same payment.

## 5. Fund the payment

Open [Fund a sandbox payment](/api-reference/sandbox/fund-a-sandbox-payment?playground=open), enter the payment ID and token, and click **Send**. No body is needed.

The sponsor sends the USDC amount agreed in the quote. The response includes its Stellar transaction reference. If the call times out, retry the **same payment ID**; retries do not send twice.

## 6. Check the result

Open [Read payment status](/api-reference/payments/read-payment-status?playground=open) with the payment ID. Repeat until `status` is **completed**.

`completed` means PI-SPI confirmed the receiving account was credited. `external_transaction_id` is the payout reference. A Stellar transaction reference alone confirms funding, not delivery to the receiver.

### View your transaction on Stellar Testnet

Open the URL returned in **`stellar_explorer_url`** inside the payment-status response, or **`stellarExplorerUrl`** in the funding response. It takes you directly to your transaction on Stellar Testnet—no hash copying or URL construction is needed.

The link is `null` until a blockchain transaction hash is available. The explorer confirms the USDC transfer; the payment's `completed` status confirms the PI-SPI payout.

[View our completed example on Stellar Testnet](https://stellar.expert/explorer/testnet/tx/794b648515a9a8f7b05e97f536c934dbdcd5bddf07516ac0331c817ed3da7d4b).

## Optional calls

You do not need the discovery or preview calls for this walkthrough. They help an integrating application list currencies, compare rates or preview a conversion. **Get a payment quote** is the call that reserves the conversion used by a payment.

## Troubleshooting

- **401**: start a new session and replace your Bearer token.
- **400**: check the receiver details, amount and delivery method.
- **409**: follow the error message. If the quote expired, obtain a new one. If payment creation is still being reconciled, retry the same request.
- **429**: the shared sandbox limit was reached. Retry later or contact Nostro.
- **Connection error**: retry shortly; if the hosted sandbox remains unavailable, contact Nostro.

The shared sponsor supports up to **50 funded payments**. Use IDs from your own responses rather than copying historical response examples.
